# CHATGPT_STOCK_WIKI_V1 운영 규칙

현재 일반 종목 누적 분석의 상위 기준문은 `INSTRUCTION_v4.7.1.md / SPEC FROZEN`이다. 이 RULES는 운영 요약이며 상위 동결본과 충돌하면 동결본을 따른다.

## 1. 독립성

ChatGPT Stock Wiki와 거래량 순환매 Wiki는 `lab.php` 및 브로커 주문과 독립한다. Wiki 기록으로 실전 주문·자본·LAB 상태를 자동 변경하지 않는다.

## 2. 데이터 시점

일반 주식 프로젝트의 공식 판정은 최근 완료 정규장 기준으로 한다.

거래량 순환매는 예외적으로:
- 완료장 = `확정상태`
- 정규장 장중 = `장중 잠정상태(P-*)`
- 현재 행동 = `확정상태 + 장중상태 + 유동성 + 기업위험 + 순환 경과일`

프리·애프터마켓·NXT는 정규장 장중상태와 구분한다.

## 3. 선행 게이트

`자료 무결성 → 기업위험 → 유동성 → 시장/섹터 → 가격·거래량 → 순환 경과일 → 상태 → 행동`

경과일은 상위 게이트를 통과한 뒤 사용하는 타이밍 보정요소이며 단독 신호가 아니다.

## 4. Wiki 갱신

Current View는 최신 유효판단으로 교체한다. Revision Timeline은 과거 기록을 삭제·수정하지 않고 append한다. 장중 중요신호는 Intraday View에 기록할 수 있다.

GitHub write가 성공하기 전에는 `저장 완료`라고 표현하지 않는다.

## 5. 거래량 순환매 GitHub 선확인

반복 질의 시 반드시 다음 순서로 확인한다.

`CURRENT.md → INDEX.md → RULES.md → VOLUME_CYCLE_FREEZE.md → 현재 FROZEN VOLUME_CYCLE_INSTRUCTION → 거래량-순환매-Wiki.md`

기억이나 이전 대화만으로 상태변경을 단정하지 않는다.

## 7. 상태 코드

확정상태: `M0 / M1 / M2 / W / S1 / S2 / S3`

장중 잠정상태: `P-M1 / P-M2 / P-W / P-S1 / P-S2 / P-S3`

- M0: 관심 소멸
- M1: 거래량 고갈, 매입 검토
- M2: 바닥 확인, 분할매입 후보
- W: 대기
- S1: 관심 증가, 신규매입 금지·매도 준비
- S2: 거래량 폭증, 분할매도
- S3: 과열, 대부분/전량매도 우선 검토

### 미국

- 100만 달러 미만: 기본 매입후보 제외

호가 공백·스프레드·역분할·상장유지·희석 위험은 금액 기준보다 우선한다.

## 9. 순환 경과일 — 6종목 필수

`주요고점`은 작은 일봉 고점이 아니라 S2/S3 계열의 거래량 팽창과 가격 이벤트가 동반된 고점을 뜻한다. 같은 이벤트가 여러 날 지속되면 하나의 고점 클러스터로 묶는다.

모든 6종목에서 반드시 다음을 관리한다.
- `last_major_peak_date`
- `peak_status`: CONFIRMED / PROVISIONAL / DATA_LIMITED
- `elapsed_calendar_days`
- `elapsed_trading_days`
- `peak_interval_sample_count`
- 평균 고점간격(달력일/거래일)
- 중앙값 고점간격(달력일/거래일)
- 최소~최대 범위
- 표본 5개 이상이면 Q1~Q3
- `data_status`: 충분 / 제한 / 부족
- `cycle_timing_status`

통계 원칙:
- 간격 표본 3개 미만: 자료부족, 평균주기 판단 금지
- 3~4개: 자료제한, 참고만
- 5개 이상: 중앙값·Q1~Q3 우선
- 이상치가 크면 평균보다 중앙값 우선
- 달력일과 거래일을 함께 표시
- 미검증 값은 추정하지 않고 `미산정/재검증 필요`로 둔다.

경과일이 역사적 평균창에 접근하면 M1/M2 후보의 우선순위를 보정할 수 있으나, 경과일만으로 매수하지 않는다. 평균을 넘었다고 급등 임박으로 표현하지 않는다.

새로운 S2/S3 주요고점이 확정되면 `last_major_peak_date`를 갱신하고 경과일을 0으로 리셋한다.

## 10. 장중 거래량 보정

최우선:
`동시간대 거래량 배율 = 현재 누적거래량 ÷ 최근 20거래일 동일 시각 평균 누적거래량`

차선:
`예상 종가 거래량 = 현재 누적거래량 ÷ 과거 평균 동일시각 누적비율`

동시간대 자료가 없으면 `현재 누적거래량 ÷ 20일 평균 일거래량`은 하한 참고값으로만 사용한다.

## 11. 매입·매도

- M1 → 분할매입 후보로 우선 검토
- M2/P-M2 → 분할매입 실행 검토
- S1/P-S1 → 신규매입 금지·매도 준비
- S2/P-S2 → 보유분 분할매도
- S3/P-S3 → 대부분 또는 전량매도 우선 검토

기본 유동성 게이트 미달이면 M1/M2라도 매입 우선후보로 올리지 않는다.

경과일은 매입 우선순위 보정에는 사용할 수 있으나 상태 코드를 단독으로 승격시키지 않는다.

## 12. 출력 형식

상태표 외에 반드시 `순환 경과일표`를 추가한다.

| 종목 | 직전 주요고점일 | 고점상태 | 달력 경과일 | 거래일 경과 | 평균/중앙값 | 범위 | 표본수 | 자료상태 | 순환 타이밍 |
|---|---|---|---:|---:|---|---|---:|---|---|

그리고 다음을 출력한다.
- 매입 우선순위
- 매도 우선순위
- 경과일상 주목 종목
- 제외·교체 사유
- Wiki 저장 여부
- 한줄 행동지시

## 13. 한줄 행동지시

`현재 순환 순서`에는 반드시 한줄 행동지시를 둔다. 상태 코드보다 강한 표현으로 자동 승격하지 않는다. 장중 P 상태를 사용하면 `(장중 잠정)`을 표시한다.

경과일이 역사적 순환창에 진입한 경우 `경과일상 주목`을 덧붙일 수 있으나 매입·매도를 확정하는 문구로 사용하지 않는다.

## 14. 저장 조건

다음 중 하나가 의미 있게 바뀔 때만 Wiki Revision Timeline을 저장한다.
- 상태 코드
- 행동
- 거래량 배율
- 유동성 등급
- 의미 있는 가격대
- 기업위험
- 감시종목 구성
- 전략 규칙
- 직전 주요고점일/고점상태
- 고점간격 평균·중앙값·범위·표본수
- 순환 타이밍 단계

경과일 숫자는 분석 시 Current View에 최신값으로 갱신할 수 있지만, 하루 경과만으로 매일 새 revision을 만들지 않는다.

## 16. 일반 전체 추천 질의 — 기존 Stock Wiki 선재검증

`추천하라`, `종목 추천`, `한국·미국·일본 추천`처럼 지정 종목 없는 일반 추천 질의에서는 거래량 순환매 Wiki와 별도로 `CHATGPT_STOCK_WIKI_V1`의 활성 종목을 신규 탐색 전에 재검증한다.

고정 순서:

`CURRENT.md → INDEX.md → RULES.md → 활성 Stock Wiki 종목 페이지 → 최근 완료장 확인 → stale/불완전 종목 외부 최신자료 재수집 → 최신 상태 재판정 → 의미 있는 변화 저장 → 신규 후보 탐색 → 기존+신규 동일기준 비교 → 국가별 최대 1종목`

원칙:

- INDEX에서 `해제`가 아닌 기존 종목은 원칙적으로 재검증 대상이다.
- 기존 종목 페이지의 완료세션이 최신 시장 완료세션보다 오래되면 과거 상태를 현재 추천 자격으로 자동 유지하지 않는다.
- 동시에 stale이라는 이유만으로 `자료 부족`으로 자동 하향하지 않는다.
- 최신 재검증 전 과거 `즉시 매입 가능`, `매입 대기`, `선발` 상태·지지·무효화·목표·손익비를 현재값으로 재사용하지 않는다.
- 시장이 WAIT/OFF이면 해당 시장 기존 종목은 위험관리·관찰·해제 판정만 하고 신규 Champion 매입을 만들지 않는다.
- 상태·구조·위험·핵심가격·행동이 의미 있게 변하면 Current View + Revision Timeline + INDEX를 동기화한다.
- 단순 종가변화나 같은 상태 반복확인은 새 Revision을 만들지 않는다.
- 필요하면 `최근 검증세션` 메타데이터만 갱신할 수 있다.
- GitHub write가 없으면 `상태 재검증: 유지 / Wiki write 없음`으로 표현한다.
- 기존 종목과 신규 종목은 동일 완료세션·동일 Champion 기준으로 비교하며 어느 쪽도 우대하지 않는다.

## 17. stale Wiki 외부자료 보강 — 필수

기존 Stock Wiki 종목이 stale이거나 기술자료가 불완전하면 `자료 부족` 판정 전에 외부 최신자료를 재수집한다.

### 가격·기술자료

- 거래소/공식 시세, 데이터 공급자, Yahoo Finance 등 금융정보서비스를 사용할 수 있다.
- 가능한 한 하나의 동일 데이터 계열에서 최근 완료세션까지 충분한 기간의 **수정 일봉 OHLCV**를 확보한다.
- MA5·20·60·120·200, ATR(14), 필요 시 20일 거래량/거래대금은 그 동일 시계열로 직접 계산한다.
- 종가는 A 사이트, MA20은 B 사이트, ATR은 C 사이트처럼 기준일·수정주가 확인 없이 섞지 않는다.

### 기업위험

가격정보 사이트만으로 기업위험 검증을 끝내지 않는다.

우선순위:

`거래소·규제기관 공시 > 기업 IR/뉴스룸 > 데이터 공급자 > 금융정보서비스 > 주요 금융언론`

증자·희석·부채·회계·감사의견·거래정지·상장유지·규제·대형 기업행동을 별도로 확인한다.

### 자료 제한/부족 판정

다음처럼 외부 재수집을 시도한 뒤에도 핵심자료를 실제 확보하지 못할 때만 사용한다.

- 최근 완료세션 OHLCV를 신뢰성 있게 확인 불가
- 이평·ATR 계산에 필요한 수정 시계열 확보 불가
- 데이터 공급원 간 기준일/수정주가 충돌을 해소할 수 없음
- 핵심 기업위험을 공식 또는 신뢰자료로 확인할 수 없음

`Wiki가 오래됐다`, `기존 문서에 ATR이 없다`, `한 사이트에 모든 지표가 없다`는 이유만으로 `자료 부족`으로 판정하지 않는다.

과거에 단순 stale만을 이유로 상태를 `자료 부족`으로 내린 기록은 삭제하지 않는다. 다음 외부 재검증에서 실제 최신 상태가 확인되면 `CORRECTION` 또는 `STATUS` Revision을 추가하여 Current View와 INDEX를 정정한다.

이 규칙의 상위 동결 기준은 `INSTRUCTION_v4.7.1.md`이다.
