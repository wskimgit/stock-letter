# CHATGPT_STOCK_WIKI_V1 운영 규칙

## 1. 독립성

ChatGPT Stock Wiki와 거래량 순환매 Wiki는 `lab.php` 및 브로커 주문과 독립한다. Wiki 기록으로 실전 주문·자본·LAB 상태를 자동 변경하지 않는다.

## 2. 데이터 시점

일반 주식 프로젝트의 공식 판정은 최근 완료 정규장 기준으로 한다.

거래량 순환매는 예외적으로:
- 완료장 = `확정상태`
- 정규장 장중 = `장중 잠정상태(P-*)`
- 현재 행동 = `확정상태 + 장중상태 + 유동성 + 기업위험 + 순환 경과일`

프리·애프터마켓·NXT는 정규장 장중상태와 구분한다.

## 3. 선행 게이트

`자료 무결성 → 기업위험 → 유동성 → 시장/섹터 → 가격·거래량 → 순환 경과일 → 상태 → 행동`

경과일은 상위 게이트를 통과한 뒤 사용하는 타이밍 보정요소이며 단독 신호가 아니다.

## 4. Wiki 갱신

Current View는 최신 유효판단으로 교체한다. Revision Timeline은 과거 기록을 삭제·수정하지 않고 append한다. 장중 중요신호는 Intraday View에 기록할 수 있다.

GitHub write가 성공하기 전에는 `저장 완료`라고 표현하지 않는다.

## 5. 거래량 순환매 GitHub 선확인

반복 질의 시 반드시 다음 순서로 확인한다.

`CURRENT.md → INDEX.md → RULES.md → VOLUME_CYCLE_FREEZE.md → 현재 FROZEN VOLUME_CYCLE_INSTRUCTION → 거래량-순환매-Wiki.md`

기억이나 이전 대화만으로 상태변경을 단정하지 않는다.

## 7. 상태 코드

확정상태: `M0 / M1 / M2 / W / S1 / S2 / S3`

장중 잠정상태: `P-M1 / P-M2 / P-W / P-S1 / P-S2 / P-S3`

- M0: 관심 소멸
- M1: 거래량 고갈, 매입 검토
- M2: 바닥 확인, 분할매입 후보
- W: 대기
- S1: 관심 증가, 신규매입 금지·매도 준비
- S2: 거래량 폭증, 분할매도
- S3: 과열, 대부분/전량매도 우선 검토

## 8. 최소 유동성 게이트

거래량이 적다는 사실 자체를 매입 신호로 보지 않는다.

### 한국
- 20일 중앙 거래대금 5억원 이상 권장
- 2억~5억원: 우선순위 감점
- 2억원 미만: 기본 매입후보 제외

### 미국
- 20일 중앙 달러 거래대금 300만 달러 이상 권장
- 100만~300만 달러: 우선순위 감점
- 100만 달러 미만: 기본 매입후보 제외

호가 공백·스프레드·역분할·상장유지·희석 위험은 금액 기준보다 우선한다.

## 9. 순환 경과일

`주요고점`은 작은 일봉 고점이 아니라 S2/S3 계열의 거래량 팽창과 가격 이벤트가 동반된 고점을 뜻한다. 같은 이벤트가 여러 날 지속되면 하나의 고점 클러스터로 묶는다.

각 종목에서 다음을 관리한다.
- `last_major_peak_date`
- `elapsed_calendar_days`
- `elapsed_trading_days`
- `peak_interval_sample_count`
- 평균 고점간격(달력일/거래일)
- 중앙값 고점간격(달력일/거래일)
- 최소~최대 범위
- 표본 5개 이상이면 Q1~Q3
- `cycle_timing_status`

통계 원칙:
- 간격 표본 3개 미만: 자료부족, 평균주기 판단 금지
- 3~4개: 자료제한, 참고만
- 5개 이상: 중앙값·Q1~Q3 우선
- 평균보다 중앙값을 우선 해석

경과일이 역사적 평균창에 접근하면 M1/M2 후보의 우선순위를 보정할 수 있으나, 경과일만으로 매수하지 않는다. 평균을 넘었다고 급등 임박으로 표현하지 않는다.

새로운 S2/S3 주요고점이 확정되면 `last_major_peak_date`를 갱신하고 경과일을 0으로 리셋한다.

## 10. 장중 거래량 보정

최우선:
`동시간대 거래량 배율 = 현재 누적거래량 ÷ 최근 20거래일 동일 시각 평균 누적거래량`

차선:
`예상 종가 거래량 = 현재 누적거래량 ÷ 과거 평균 동일시각 누적비율`

동시간대 자료가 없으면 `현재 누적거래량 ÷ 20일 평균 일거래량`은 하한 참고값으로만 사용한다.

## 11. 매입·매도

- M1 → 분할매입 후보로 우선 검토
- M2/P-M2 → 분할매입 실행 검토
- S1/P-S1 → 신규매입 금지·매도 준비
- S2/P-S2 → 보유분 분할매도
- S3/P-S3 → 대부분 또는 전량매도 우선 검토

기본 유동성 게이트 미달이면 M1/M2라도 매입 우선후보로 올리지 않는다.

경과일은 매입 우선순위 보정에는 사용할 수 있으나 상태 코드를 단독으로 승격시키지 않는다.

## 12. 출력 형식

상태표 외에 반드시 `순환 경과일표`를 추가한다.

| 종목 | 직전 주요고점일 | 달력 경과일 | 거래일 경과 | 평균 고점간격 | 중앙값 | 범위/Q1~Q3 | 표본수 | 순환 타이밍 |
|---|---|---:|---:|---:|---:|---|---:|---|

그리고 다음을 출력한다.
- 매입 우선순위
- 매도 우선순위
- 경과일상 주목 종목
- 제외·교체 사유
- Wiki 저장 여부
- 한줄 행동지시

## 13. 한줄 행동지시

`현재 순환 순서`에는 반드시 한줄 행동지시를 둔다. 상태 코드보다 강한 표현으로 자동 승격하지 않는다. 장중 P 상태를 사용하면 `(장중 잠정)`을 표시한다.

경과일이 역사적 순환창에 진입한 경우 `경과일상 주목`을 덧붙일 수 있으나 매입·매도를 확정하는 문구로 사용하지 않는다.

## 14. 저장 조건

다음 중 하나가 의미 있게 바뀔 때만 Wiki Revision Timeline을 저장한다.
- 상태 코드
- 행동
- 거래량 배율
- 유동성 등급
- 의미 있는 가격대
- 기업위험
- 감시종목 구성
- 전략 규칙
- 직전 주요고점일
- 고점간격 통계/표본수
- 순환 타이밍 단계

경과일 숫자는 분석 시 Current View에 최신값으로 갱신할 수 있지만, 하루 경과만으로 매일 새 revision을 만들지 않는다.

## 15. 버전관리

- `v1.0.0` RELEASED_HISTORY
- `v1.1.0` HISTORY
- `v1.2.0` FROZEN_HISTORY
- `v2.0.0` FROZEN_HISTORY
- `v2.1.0` **FROZEN**

현재 동결본을 직접 수정하지 않는다. 향후 변경은 새 버전 파일로 생성한다.
